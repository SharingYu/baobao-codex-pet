# 定制宠物交付闭环

这套流程用于把客户提供的真实宠物素材，交付成可在“宠物桌伴”程序里导入使用的 `.petpack`。首轮用包包和菲菲验证，程序与宠物内容彼此独立：升级程序不会清空宠物记忆，更新宠物包也不会覆盖用户状态。

## 1. 客户提交

建议收集 5–10 张清晰照片和 1–3 段短视频：

- 正脸、左右侧脸、全身站立、坐姿、尾巴和典型花纹。
- 宠物常戴的项圈、铃铛或衣服应至少有一张清晰特写。
- 视频优先收集走路、回头、趴下、扑玩具等能体现性格的动作。
- 同时确认名字、品种、性格关键词、喜欢的食物和玩具。

原始素材只进入私有工作目录，不提交到公开仓库；交付包只包含重新绘制后的透明动画资产和声明式配置。

## 2. 生成与质检

首版动作基线：

1. 待机与眨眼。
2. 向左、向右移动。
3. 摸摸后的开心反应。
4. 投喂后的靠近与接受反应。
5. 追球或扑逗猫棒。
6. 等待、安静陪伴和 16 个注视方向。

每次交付至少检查：

- 毛色、脸型、眼睛、花纹、尾巴和标志性饰品是否像本人。
- 每格透明背景是否干净，脚底是否稳定，循环动画是否跳帧。
- 图集尺寸、行列和动画帧数是否与 manifest 一致。
- 缩放到桌面实际尺寸后是否仍清楚，不出现白边、黑边或裁切。

## 3. 转换与打包

已有 Codex v2 宠物可直接转换成通用目录包：

```powershell
node tools/petpack/convert-codex.mjs --input pets/baobao --output petpacks/baobao
node tools/petpack/convert-codex.mjs --input pets/feifei --output petpacks/feifei
```

交付前先验证，再生成单文件：

```powershell
node tools/petpack/cli.mjs validate petpacks/baobao
node tools/petpack/cli.mjs pack petpacks/baobao release/petpacks/baobao.petpack
node tools/petpack/cli.mjs validate release/petpacks/baobao.petpack
```

`.petpack` 是受约束的 ZIP 容器，只允许 manifest 声明的图片等被动资源。导入器会拒绝路径穿越、符号链接、可执行内容、超大文件、哈希不匹配和未声明文件。

Alpha 客户包必须采用 Codex v2 的 `192 × 208` 单格、`8 × 11` 图集布局；程序会拒绝当前不能正确渲染的其他布局，而不是静默导入。

## 4. 客户安装

1. 安装并启动“宠物桌伴”。
2. 点击浮动操作条右侧的导入按钮。
3. 选择收到的 `.petpack`。
4. 导入成功后，宠物立即进入桌面；无需 Codex。
5. 摸摸一次、投喂一次、玩一次小球，确认完整互动链路。
6. 退出并重启程序，确认位置、安静模式和互动次数已恢复。

同一个宠物 ID 默认不会被静默覆盖。更新包应提升 `packageVersion`（后续格式字段），由用户明确确认升级，避免误覆盖定制内容。

## 5. 首轮验收清单

包包与菲菲需要共同通过以下闭环：

- [ ] 两个宠物包均通过安全验证。
- [ ] 开发模式和安装版本都能加载两只宠物。
- [ ] 可分别拖动、摸摸，并有动作反馈。
- [ ] 三种食物可投放，最近的宠物会靠近并反馈。
- [ ] 小球、逗猫棒、纸箱均可触发互动。
- [ ] 安静模式会停止主动邀请，但不让宠物消失。
- [ ] 状态保存后重启可恢复。
- [ ] 新 `.petpack` 可通过程序选择器导入，失败时显示可理解的原因。
- [ ] 空白桌面区域可以正常点穿，托盘始终提供显示、隐藏和退出。

## 6. 交付与售后

建议每单保留交付清单、manifest 哈希和生成版本，但不长期保留原始照片。客户确认交付或退款后 24 小时内删除活动存储中的源素材；备份最迟 30 天清除。返工只修改宠物资产，不要求客户重装程序或丢失已有记忆。
